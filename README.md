#Project Overview

Fake news has become one of the major challenges of the digital era. With the rapid growth of online news platforms and social media, misleading information spreads quickly and influences public opinion. This project develops a machine learning-based system capable of classifying news articles as **Fake** or **Real** using Natural Language Processing (NLP) techniques.

The project applies data preprocessing, feature extraction, exploratory data analysis, and supervised machine learning algorithms to build an effective fake news detection model.

---

#Problem Statement

The widespread dissemination of fake news through digital platforms makes it difficult for users to verify the authenticity of information. Manual verification is time-consuming and often unreliable. Therefore, there is a need for an automated system that can accurately distinguish fake news from genuine news articles.

---

#Project Objectives

- Develop an automated fake news detection system.
- Clean and preprocess textual news data.
- Perform Exploratory Data Analysis (EDA).
- Extract meaningful text features using TF-IDF.
- Train and evaluate machine learning classification models.
- Predict whether a news article is Fake or Real.

---

#Dataset

This project uses the **WELFake Dataset**, which contains thousands of labeled news articles collected from multiple online news sources.

Dataset Features include:

- Title
- News Text
- Label (Real/Fake)

**Label meaning:** `0` = Real news, `1` = Fake news.

The raw CSV is not stored in this repository (it's ~245MB — too large for git). See [Getting the dataset](#getting-the-dataset) below for how to get it.

## How the code fits together

This is a classic ML pipeline split into two parts: **train once** (the notebook) and **serve forever** (the Flask app).

**1. `01_eda.ipynb` — train the model (run this once, offline)**

| Step | What happens |
|---|---|
| Load data | Reads `data/WELFake_Dataset.csv` into a pandas DataFrame |
| Clean | Drops rows with missing title/text; for every article: lowercases it, strips out anything that isn't a letter (numbers, punctuation, emoji), and removes common "stopwords" (*the, is, and...*) that don't help tell fake from real |
| Save cleaned data | Writes the cleaned text out to `data/WELFake_cleaned.csv` so you can inspect it |
| Vectorize | Converts the cleaned text into numbers using **TF-IDF** (a score per word that's high when a word is common in *this* article but rare across *all* articles — i.e. distinctive words). Capped at the 5,000 most useful words |
| Split | 80% of the data trains the model, 20% is held back to test it on articles it's never seen |
| Train & compare | Trains 3 different algorithms (Logistic Regression, Naive Bayes, Decision Tree) and prints their accuracy so you can pick a winner |
| Save the winner | Logistic Regression scored highest (~95% accuracy), so it's retrained and saved to `models/best_model.pkl`. The fitted TF-IDF vectorizer is saved to `models/data.pkl` — `app.py` needs this exact vectorizer to turn new text into the same kind of numbers the model was trained on |
| Evaluate | Generates a confusion matrix and a precision/recall/F1 report so you can see exactly where the model gets things right or wrong |
| Sanity check | A tiny manual test at the end runs a couple of made-up headlines through the trained model as a smell test |

**2. `app.py` — serve predictions (run this every time you want to use the app)**

- On startup, loads `models/best_model.pkl` (the classifier) and the TF-IDF vectorizer from `models/data.pkl`.
- Exposes three routes:
  - `GET /` — serves `templates/index.html` (the web UI)
  - `GET /health` — returns `{"status": "ok"}`, useful to check the server is alive
  - `POST /predict` — takes `{"text": "..."}`, cleans it with the *same* cleaning steps used in training, vectorizes it with the *same* TF-IDF vectorizer, and returns `{"label": "FAKE"|"REAL", "confidence": <percent>}`
- **Decision rule:** a prediction is only labelled `FAKE` if the model is more than 75% confident — otherwise it defaults to `REAL`. This is a deliberate bias toward fewer false "fake" accusations (see `app.py` for the exact line and reasoning).

**3. `templates/index.html` — the UI**

- A single HTML file with 5 tabs, switched client-side with JavaScript (no page reloads):
  - **Home** — landing page
  - **Analysis** — the real feature: paste text, it calls `POST /predict` on `app.py` and shows the verdict + confidence bar
  - **Assistant** — a chat UI that *tries* to call the Anthropic API directly from the browser with no key, which always fails by design (you should never put an API key in client-side code), so it silently falls back to a handful of canned media-literacy tips
  - **News Center** / **Dashboard** — demo pages with hardcoded example data (not connected to the real model or a database); included for presentation purposes

## Getting Started (run it locally)

### 1. Get the dataset
Download the WELFake dataset CSV and place it at `data/WELFake_Dataset.csv` (create the `data/` folder if it doesn't exist). It's publicly available from Kaggle ("Fake News Classification" by saurabhshahane) or its Zenodo mirror.

### 2. Set up Python
```bash
cd "fake-news-detection-project"
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Train the model
Run the notebook top to bottom — this creates everything in `models/` and `data/WELFake_cleaned.csv`:
```bash
jupyter notebook 01_eda.ipynb
```
Run each cell in order (Cell → Run All). This takes a few minutes — text cleaning and model training are the slow parts.

### 4. Start the web app
```bash
python app.py
```
Open **http://127.0.0.1:5000** in your browser.

> macOS note: port 5000 sometimes conflicts with AirPlay Receiver. If you see `Address already in use`, either turn off AirPlay Receiver (System Settings → General → AirDrop & Handoff), or run on another port: `python -c "import app; app.app.run(port=5050)"` and visit `http://127.0.0.1:5050`.

### 5. Try it
Paste a headline or article into the **Analysis** tab and click **Run AI Analysis**.

## Model Performance

| Model | Accuracy |
|---|---|
| **Logistic Regression** (used in the app) | **94.95%** |
| Decision Tree | 91.45% |
| Naive Bayes | 85.04% |

On the held-out test set, Logistic Regression scores ~95% precision/recall/F1 on both Real and Fake classes (see `models/confusion_matrix.png` after training, or the notebook's evaluation cell).

## Known Limitations

- The model is text-only — it judges *how an article is written*, not whether its claims are factually true, so well-written fake news or poorly-written real news can fool it.
- `data/` and `models/` are excluded from git (`.gitignore`) because they're large/generated files — they must be created locally by following the steps above.
- The Assistant chat tab and the News Center/Dashboard tabs use placeholder/static content; only the Analysis tab is connected to the real trained model.
